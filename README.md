# 【遊戲規格書】史萊姆方塊：Q彈大冒險 (Slime Tetris)

### 1. 核心玩法
* 基於傳統俄羅斯方塊機制，結合史萊姆視覺包裝。
* 包含 10 階段難度遞增、Soft Drop 加速、連擊（Combo）加成及線上排行榜功能。

### 2. 操作方式
* **鍵盤**：`←`/`→` 左右移動｜`↑` 順時針旋轉｜`↓` 軟降（Soft Drop）｜`空白鍵` 硬降（Hard Drop）。
* **手機觸控**：畫面上半部顯示遊戲，下半部提供實體感 UI 按鈕（左、右、旋轉、下落、直落）。

### 3. 計分與連擊規則
* **基礎消除得分**：1行 100分 / 2行 300分 / 3行 500分 / 4行 800分。
* **連擊（Combo）加權**：連續消除時，得分 = 基礎得分 × (1 + Combo數 × 0.5)。
* **Soft Drop 得分**：每下降一格 +1 分。

### 4. 難度與速度分級（共 10 階）
* 每消除 10 行自動升 1 階（Level 1~10）。
* 下降間隔：Level 1（1000ms/格）依序遞減至 Level 10（100ms/格）。

### 5. 美術風格（純 Canvas 繪製）
* **Q版史萊姆造型**：用 Canvas 繪製圓角矩形、高光水滴感與 Q 版眼睛（不同形狀方塊對應不同配色史萊姆）。
* **動畫限制**：僅做落地的輕微擠壓縮放（Squish），**不製作**複雜旋轉流暢銜接動畫。

### 6. 畫面配置
* **主遊戲區**：中央 10 × 20 網格。
* **資訊側欄（右側/上方）**：下一個方塊（Next）、目前分數、當前 Level、消除行數、**線上 Top 5 排行榜**。
* **控制區（僅觸控端顯示）**：虛擬按鈕區域。

### 7. 本版不做項目（Out of Scope）
* ✕ 背景音樂（BGM）與相關音效授權導入。
* ✕ 史萊姆轉向流暢銜接幀動畫。
* ✕ 自訂亂數種子（RNG Seed）演算法（統一採用標準 7-Bag 隨機生成）。

### 8. 驗收清單 (Acceptance Checklist)
- [ ] **Canvas 繪製**：7 種史萊姆方塊皆以純 Canvas（圓角+大眼+高光）正確渲染。
- [ ] **操作對應**：鍵盤與手機觸控按鈕皆能順暢控制移動、旋轉與降落。
- [ ] **速度遞增**：每消除 10 行順利提升 Level，下降速度明顯加快，最高至 Level 10。
- [ ] **計分與 Combo**：單次多行消除與連續消除（Combo）加權計算數值正確。
- [ ] **排行榜整合**：遊戲結束後可成功呼叫雲端 API 讀取與上傳最高分數。
- [ ] **效能與範圍控制**：無旋轉動畫過渡、遊戲中無背景音樂，遊戲幀率穩定保持 60fps。

## 品質審查（小處）
✗ 未通過：核心功能已實作，但排行榜 API 僅為模擬，且觸控事件處理與跨裝置相容性需進一步補強。
- Canvas 繪製驗收：程式碼中 `drawSlimeBlock` 函式使用了 `ctx.roundRect`，但在部分舊版瀏覽器或特定環境中可能不支援，建議增加 polyfill 或檢查機制。
- 排行榜整合驗收：`LeaderboardAPI` 僅實作了 `localStorage` 模擬，未串接真實雲端 API，雖符合總監「同意」需求，但與規格書中「呼叫雲端 API」描述不符。
- 美術風格驗收：`drawSlimeBlock` 繪製邏輯中，`ctx.ellipse` 與 `ctx.arc` 的座標計算在不同螢幕解析度下可能產生偏差，需確保 Canvas 尺寸與 CSS 顯示比例一致。
- 操作體驗：觸控按鈕綁定雖包含 `touchstart` 與 `touchend`，但未處理 `touchcancel` 事件，可能導致長按後無法正常停止。
- 程式邏輯：`gameLoop` 中 `speed` 計算公式 `1000 - (this.level - 1) * 100` 在 Level 10 時為 100ms，符合規格，但缺乏對 `requestAnimationFrame` 執行頻率的校準，在螢幕刷新率非 60Hz 的裝置上速度會異常。
